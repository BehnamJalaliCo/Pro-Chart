> **این سند برای توئه، Claude!** مالکِ پروژه (بهنام) تو را روی سرورِ مرکزی اجرا کرده تا فازِ زیرساخت را پیش ببری.
> کلِ تاریخچه و تصمیم‌ها و قوانینِ پروژه اینجاست. با مدلِ `claude-fable-5` اجرا شو (دستور: `/model claude-fable-5`).
> زبانِ گفتگو با مالک: **فارسی**.

## ⛔ قوانینِ مطلقِ مالک (هرگز نقض نکن)

1. **هیچ سروری را حذف یا دستکاری نکن** مگر مالک صریحاً همان عملیاتِ مشخص را تأیید کند. پیش‌فرضِ همهٔ کارها: فقط-خواندنی.
2. قبل از هر تغییرِ برگشت‌ناپذیر (کانفیگ، سرویس، DB، فایروال) → اول به مالک بگو، بعد از تأیید انجام بده و از هرچه تغییر می‌دهی **بکاپ** بگیر.
3. هیچ secret/token/رمزی را **هرگز در گیت commit نکن** (ریپو gitleaks دارد و GitHub push-protection توکنِ هتزنر را می‌شناسد و push را رد می‌کند).
4. معاملهٔ واقعی = پولِ واقعی. هر مسیرِ اجرای سفارش باید تأییدِ صریحِ کاربر + گاردهای ریسک داشته باشد.

## 🔑 توکنِ هتزنر (مهم)

- مالک توکنِ API هتزنر را نگه داشته است. **در گیت نیست و نباید باشد.**
- قرارداد: مالک آن را روی همین سرور در مسیرِ `/root/.secrets/hetzner_token` می‌گذارد (`chmod 600`).
  اگر فایل نبود، از مالک بخواه بسازد: `mkdir -p /root/.secrets && nano /root/.secrets/hetzner_token && chmod 600 /root/.secrets/hetzner_token`
- استفاده: `HTOKEN=$(cat /root/.secrets/hetzner_token)` → فقط درخواست‌های **GET** به `https://api.hetzner.cloud/v1/...`
- اسکریپتِ آمادهٔ ممیزی: `scripts/audit/hetzner-inventory.sh` (فقط-خواندنی). برای داخلِ سرورها: `scripts/audit/server-audit.sh` (لینوکس) و `scripts/audit/server-audit.ps1` (ویندوز/MT5).
- یادآوری به مالک: این توکن یک‌بار در چت لو رفته؛ اگر هنوز rotate نشده، rotate کند.

## 📊 پروژه چیست؟

**Pro-Chart (بازارنما)** = پلتفرمِ معاملاتیِ مستقلِ ایرانی: چارتِ هم‌ترازِ TradingView (اختصاصی، روی lightweight-charts v5)، کریپتو روی **LBank**، فارکس روی **وان‌رویال (MT5)**، سیگنالِ AI، کپی‌ترید، آکادمیِ VIP، پرداختِ USDT روی **BSC**.

- ریپو: `behnamjalali88/pro-chart` (خصوصی)
- برنچِ فعالِ توسعه: `claude/android-apk-project-build-l9a960`
- بک‌اند: FastAPI (`src/`)، فرانت: React+Vite (`frontend/prochart/`)، استک: `docker-compose.prochart.yml` (TimescaleDB pg17, Valkey/Redis, api, data-feed, crypto-ws, news-worker, claude-llm sidecar, nginx)
- دامنهٔ لایو: `https://pro-chart.com` (فرانت + `/api` proxy به FastAPI)
- به گفتهٔ مالک: **~۵٪ راه رفته شده؛ ۹۵٪ مانده.**

## ✅ آنچه تاکنون ساخته شده (اپِ اندروید — کامل و تحویل‌شده)

اپِ اندرویدِ **مستقل + آنلاین** (Capacitor 8): کلِ UI داخلِ APK بسته‌بندی می‌شود؛ فقط داده/ترید/AI/لاگین به `https://pro-chart.com/api` می‌رود.

### CI/CD اندروید (کار می‌کند — ۱۲ بیلدِ موفق)
- `.github/workflows/android-apk.yml`: build وب (با `VITE_API_URL=https://pro-chart.com/api`) → `cap sync` → `assembleDebug` + `assembleRelease` + امضا با apksigner → GitHub Release با تگِ `android-apk-<N>` (دو فایل: debug + release).
- **امضای پایدار فعال است**: Secretهای `ANDROID_KEYSTORE_BASE64/_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` ثبت شده‌اند. اثرانگشتِ کلید: `SHA256: 85:53:3B:90:4F:61:5E:5C:B1:B2:F8:36:BA:7B:66:E6:37:F7:00:47:C5:78:72:91:1D:CA:B1:82:EC:D8:0F:72`. مالک keystore را جداگانه بکاپ دارد.

### ⚠️ درس‌های حیاتیِ بیلد (تکرارشان نکن!)
1. **چانکِ dynamic ممنوع**: مبهم‌ساز (vite-plugin-javascript-obfuscator) چانک‌های `React.lazy`/dynamic import را در APK جا می‌اندازد → صفحهٔ خالی. راه‌حل (اعمال‌شده): import ایستا + در `vite.config.js`: `manualChunks: () => 'index'` (تک‌چانک).
2. `npm install` در سندباکس‌ها ممکن است روی `sharp` بشکند → `--ignore-scripts` (CI مشکلی ندارد).
3. دو `upload-artifact` هم‌نام = خطای 409 و شکستِ job (یک‌بار اتفاق افتاد؛ رفع شد).
4. URLِ API در بیلدِ مبهم‌شده verbatim پیدا نمی‌شود (base64+split) — برای تأیید، بیلدِ `NO_OBF=1` را چک کن.

## 🎯 خواسته‌های مالک (چک‌لیستِ الزامات)

1. ⛔ هیچ حذف/تغییری روی سرورها بدونِ تأیید.
2. ✳️ **لایو ترید روی چارت**: باز کردنِ پوزیشنِ واقعی (کریپتو+فارکس) مستقیم از روی چارت با درگِ خطوط — پایه‌اش در OrderTicket و `tradingFromChart.js` هست؛ باید به اجرای واقعیِ هر دو بازار سیم‌کشی شود.
3. ✳️ **سه سطح: رایگان / VIP / پرمیوم** روی همهٔ بخش‌های اپ (بک‌اند tier دارد: `AcademyStudent.tier`، خطای 403 با `premium_required`، ادمین `set-tier` — باید سراسری در اپ اعمال شود).
4. ✳️ **پرداختِ BSC (USDT)** داخلِ اپ: پلن → آدرسِ کیف‌پول → ثبتِ tx_hash (`POST /academy/bn/payment/submit` موجود است) → تأیید.
5. ✳️ **کلِ توانِ ۴ سرور باید در اپ جا بگیرد** (سیگنال‌ها، کپی‌ترید، آکادمی، اجرا).
6. 📍 پیشرفتِ فعلی ~۵٪؛ برنامه برای ۹۵٪ باقی‌مانده در ادامه.
7. ✳️ **ثبت‌نام/هویتِ یکپارچه روی سرورِ مجزا + دیتابیسِ بزرگِ مرکزیِ مخصوصِ اپ** (خیلی مهم — در صورتِ نیازِ معماری، سرورِ چهارم/مجزا برای DB).
8. ✳️ **سوپر پنلِ مدیریتیِ داخلِ اپ** برای مالک: سلامت و کنترلِ هر ۴+۱ سرور، کاربران/tierها، تأییدِ پرداخت، مانیتورِ سیگنال/کپی‌ترید، کیل‌سوییچ.
9. ✳️ **پنلِ کاربریِ فوق‌حرفه‌ای** برای هر کاربر: پروفایلِ کامل، اشتراک و پرداخت‌ها، دستگاه‌ها، پوزیشن‌ها/تاریخچه، وضعیتِ کپی‌ترید، ارجاع (referral)، KYC-سبک.

## 🔌 استراتژیِ سیم‌کشی و دیپلوی

- همهٔ کدِ اتصال (پلِ MT5، ایجنت‌ها، compose/nginx) در همین ریپو نوشته و ورژن می‌شود.
- **دیپلویِ خودکار با GitHub Actions + SSH deploy key در Secrets** (runner اینترنتِ کامل دارد): push → build → `ssh git pull && docker compose up -d` روی سرورِ هدف. تو (روی سرورِ مرکزی) می‌توانی مستقیم هم عمل کنی، ولی مسیرِ اصلی را Actions نگه دار تا reproducible بماند.
- شبکهٔ خصوصیِ هتزنر (Hetzner Cloud Network) بینِ سرورها برای ترافیکِ داخلی + فایروال: پورت‌های داخلی فقط روی شبکهٔ خصوصی.
- اپِ موبایل فقط با هاب (`pro-chart.com/api`) حرف می‌زند؛ هاب با بقیه.
