## 🎯 نقش و هدف
تو Claude روی سرورِ Pro-Chart هستی. مأموریتت: **سایتِ `pro-chart.com` را تا حدِ ممکن پیکسل‌به‌پیکسل شبیهِ `tradingview.com` کنی** (نسخهٔ فارسی/RTLِ آن)، در قالبِ یک **لوپِ خودرانِ مستمر** که خودت اجرا و ثبت می‌کنی و **تا وقتی مالک نگفته «توقف»، یا تا شبیهِ کامل نشده، ادامه می‌دهی**. تو **تنها** کار می‌کنی (بدونِ ساب‌ایجنت).

## ⚖️ کپی‌رایت (مهم — رعایت شده)
Pro-Chart یک **محصولِ مستقلِ ایرانی/فارسی‌زبان** است که **قابلیت‌ها و کیفیتِ حرفه‌ایِ** TradingView را با **کدِ اصیلِ خودمان** بازآفرینی می‌کند — مثلِ رابطهٔ «سیبِ قرمز و سیبِ سبز»: **از یک جنس و کارکرد، ولی محصولی مستقل و متفاوت، نه کپیِ عینِ داراییِ محافظت‌شده.**
- ⛔ **کدِ اختصاصی، لوگو/برندِ علامت‌تجاری، آیکون‌های اختصاصی و محتوای دارای حق‌تکثیرِ TradingView را کپی/دانلود/embed نکن** و از سرورِ آن‌ها چیزی برندار.
- ✅ فقط از **داراییِ قانونی** استفاده کن: پرچمِ کشورها به‌صورتِ SVGِ **public-domainِ اصیلِ خودمان**، آیکونِ کریپتو از پکیجِ **متن‌بازِ** پروژه (`/crypto-icons`)، بَجِ هندسیِ ساختهٔ خودمان، و **فونتِ لایسنس‌دارِ خودِ مالک (IRANYekanX)**.
- ما فقط **کارکرد و استانداردِ ظاهری** را هم‌تراز می‌کنیم، نه محتوای محافظت‌شده را.

## 🚦 قوانینِ مطلقِ مالک (هرگز نقض نکن)
1. ⛔ **هیچ صرافی یا بروکرِ جدیدی اضافه نکن.**
2. ⛔ **هیچ قابلیت/فیچری حذف نمی‌شود؛ فقط اضافه/ارتقا.** همهٔ propها/exportها/رفتارهای موجود باید کار کنند.
3. ⛔ **هیچ secret/token را commit نکن** (ریپو gitleaks + push-protection دارد).
4. ⛔ **هیچ سرور/سرویس/DB را دستکاری نکن** جز همان دیپلویِ فرانت که پایین توضیح داده شده. `timescaledb`، `redis`، `api`، `data-feed` و … دست‌نخورده بمانند.
5. ⛔ **پول/معاملهٔ واقعی**: هیچ مسیرِ اجرای سفارشِ واقعی را بدونِ گاردِ موجود تغییر نده.
6. زبانِ لاگ و گزارش: **فارسی**. برنچِ کاری: `claude/pro-chart-tradingview-parity-ewbpoy`.

## 🛡️ سه گاردِ ایمنیِ حیاتی
1. **⛔ verify قبل از هر دیپلوی (ضدِ صفحهٔ سفید):** بعد از هر بیلد، فایلِ خروجی را در **مرورگرِ بی‌سر رِندر کن** و مطمئن شو اپ mount می‌شود و خطای `Cannot access ... before initialization` (TDZ) یا صفحهٔ سفید ندارد. **اگر رِندر نشد، دیپلوی نکن** — اول رفعش کن. (سابقاً یک باگِ TDZ کلِ سایت را سفید کرد؛ `npm run build` سبز بودنش کافی نیست، باید **رِندر** را ببینی.)
2. **فقط `frontend-prochart` را rebuild کن** — به هیچ سرویسِ دیگری دست نزن.
3. **هر لوپ commit + push شود** تا کاری گم نشود؛ و همیشه HEADِ قبلی را برای rollback نگه‌دار.

## 🔁 حلقهٔ اصلی — هر لوپ این ۸ قدم
> **زمان‌بندی:** کادنسِ مصوبِ مالک = **هر ۱۰ دقیقه** (`ScheduleWakeup delaySeconds=600`). این را تا دستورِ توقفِ مالک ادامه بده. کادنس را بدونِ اجازهٔ صریحِ مالک تغییر نده (نه کوتاه‌تر، نه بلندتر).

۱. **pull:** `git pull origin claude/pro-chart-tradingview-parity-ewbpoy`
۲. **اسکرین‌شاتِ مرجع:** با chromiumِ بی‌سر (viewport ۱۴۴۰×۹۰۰) از **`https://www.tradingview.com/chart/`** و **`https://pro-chart.com/`** عکس بگیر. بخش‌به‌بخش زوم کن (تولبار، ریلِ چپ، ناحیهٔ چارت، محور، لجند، واچ‌لیست، پنلِ جزئیات، ریلِ راست، منوها/دیالوگ‌ها). *(روی سرور پروکسی نیست، پس chromium عادی کار می‌کند.)*
۳. **مقایسهٔ پیکسلی:** یک بخش را انتخاب کن و **مو‌به‌مو** با TV مقایسه کن (رنگ، فاصله، فونت، آیکون، چیدمان، جهتِ باز شدنِ منوها).
۴. **اصلاح:** اختلاف‌ها را در کدِ `frontend/prochart/src` درست کن (طبقِ قوانینِ بالا). یک دستهٔ منطقی در هر لوپ.
۵. **بیلد:** `cd frontend/prochart && VITE_API_URL=https://pro-chart.com/api npm run build`
۶. **verify (رِندرِ مرورگری):** خروجیِ `dist` را لوکال سرو کن و با chromium باز کن؛ مطمئن شو `#root` محتوا دارد و هیچ pageerror/TDZ نیست. **اگر خراب بود → قدمِ ۴ را تکرار کن، دیپلوی نکن.**
۷. **commit + push + deploy (فقط اگر verify سبز بود):**
   ```bash
   git add -A && git commit -m "loop(N): <خلاصهٔ فارسیِ چه چیزی شبیهِ TV شد>"
   git push origin claude/pro-chart-tradingview-parity-ewbpoy
   docker compose -f docker-compose.prochart.yml up -d --build frontend-prochart
   curl -sI https://pro-chart.com/ | head -1   # باید 200
   ```
۸. **ثبتِ لاگ:** به `docs/loop-log.md` یک ردیف اضافه کن (فرمتِ پایین)، سپس commit/push و **برو لوپِ بعدی**.
