# گزارشِ M2 — سرویسِ Auth مرکزی + DB مرکزی            وضعیت: ✅ کامل (سمتِ سرور)

## چه شد (خلاصهٔ ۵ خطی)
- سرویسِ Auth مرکزی (RS256/JWKS) روی سرورِ مرکزی دیپلوی شد و کامل تست شد (۹ سناریو).
- PostgreSQL مرکزی (`central_identity`) بالا آمد؛ Docker + Compose روی سرورِ مرکزی نصب شد.
- هر ۷ کاربرِ فعلیِ `academy_students` با هشِ رمز به جدولِ `identities` مرکزی مهاجرت کردند (idempotent، بدونِ نوشتن روی مبدأ).
- پچِ آمادهٔ سمتِ اپ برای پذیرشِ توکنِ مرکزی نوشته شد (`M2-APP-HANDOFF-PATCH.md`).
- کلیدِ خصوصی و رمزها هرگز در گیت نیستند؛ سازگاریِ عقب‌رو با HS256 برای گذارِ بی‌قطعی تعبیه شد.

## جزئیاتِ فنی
| مورد | مقدار |
|---|---|
| سرویس | `central-auth` روی `127.0.0.1:8100` (سرورِ مرکزی 91.107.183.210) |
| دیتابیس | `central-postgres` (postgres:17) روی `127.0.0.1:5442`، DB `central_identity` |
| امضا | RS256، `kid=central-2026-07`، JWKS در `/.well-known/jwks.json` |
| کلیدها | `central-auth/keys/` روی سرور (gitignore)، خصوصی chmod 600 |
| کد | `central-auth/` (FastAPI+SQLAlchemy async)، مدلِ `identities/devices/refresh_tokens/signing_keys/audit_log` |
| Endpointها | login, guest, refresh(چرخشی), logout, me, admin/set-tier, jwks, health |
| مهاجرت | `central-auth/scripts/migrate_students.py` — ۷ کاربر (۳ premium، ۴ free) |

**تست‌های تأییدشده:** لاگین (یوزر/ایمیل)، ردِ رمزِ غلط (۴۰۱)، me با/بدونِ توکن (۲۰۰/۴۰۱)، چرخشِ refresh + ابطالِ توکنِ کهنه (۴۰۱)، سقفِ ۲ دستگاه (۴۰۹)، گیتِ ادمینِ set-tier (۴۰۳). مهاجرت: idempotent (اجرای دوم ۰ ساخت/۷ به‌روزرسانی)، هر ۷ هش معتبرِ bcrypt، بدونِ تکراری.

## چیزهایی که تغییر دادم (+ تأییدِ مالک)
1. **نصبِ Docker 29.6.1 + Compose v5.2.0** روی سرورِ مرکزی + افزودنِ `Hub` به گروهِ docker — مالک: «هرچه در سند است انجام بده» + سرورِ مرکزی خالی و هدفِ M2 بود.
2. **بالا آوردنِ استکِ `central-auth`** روی سرورِ مرکزی (کانتینرهای ایزوله، فقط 127.0.0.1).
3. **خواندنِ فقط-خواندنیِ `academy_students`** از DB فارکس برای مهاجرت (هیچ نوشتنی روی فارکس).
- روی سرورهای فارکس/کریپتو/هابِ **زنده** هیچ تغییری داده نشد.
